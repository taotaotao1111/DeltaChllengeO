# 物语千年 · DeltaChllengeO

一个让文物用第一人称讲完自己一生的框架。React + TypeScript + Vite 单页应用，通过场景切换叙事，并提供具备「事实边界护栏」的 AI 角色扮演对话。何尊主线分为「第一幕·相遇」「第二幕·发现」「第三幕·重逢」，目标约 3～5 分钟（不含自选深入与自由对话）；长信宫灯档案待核实，暂未开放。

**新增一件文物 = 在 `src/data/artifacts/` 下加一个档案文件 + 在 `index.ts` 注册表里登记一行**，组件层无需改动。

## 开发

代码在 `frontend/`（`backend/` 是 Cowork 部署用的托管服务）：

```bash
cd frontend
npm install
npm run dev              # 开发服务器
npm run build            # 档案自检 + 类型检查 + 生产构建
npm run lint             # ESLint
npm run preview          # 预览生产构建
npm run check:artifacts  # 只跑档案自检
npm run check:narrative  # 三幕跳转、铭文分支和探索记忆核验
npm run check:chat       # 情境快照、短答、原位返回与计时暂停核验
npm run check:interactions # 手机全屏、累计时间线、视频音乐恢复与静音选择核验
npm run check:evidence   # 三类 AI 证据联动、目标校验、原位返回与记忆记录核验
npm run check:memory     # 记忆海报真实计数、个人内容和长文本排版核验
```

## 叙事流程

应用只有两条真实路由（`/` 和 `/sources`）。`/` 内部的流程由 `src/store/gameStore.ts` 的 `stage` 驱动，而非 react-router：

```
museum → gallery → chapter（第 chapterIndex 章，章数由该文物档案决定）→ timeline（可选）
```

章节不写死数量：`ChapterHost` 读出当前文物的第 N 章，按 `module.kind` 分发给对应模块组件（`observe` 观察 / `qa` 问答 / `reveal` 揭示）。模块不知道自己是第几章，只收到 `onNext` / `onBack`，所以只做一章的文物同样成立。

新增一种叙事玩法 = 加一个 `kind` + 一个模块组件，已有 kind 一行都不用动。

AI 对话与记忆卡是贯穿全程的全局能力，同样由 `gameStore` 管理。

何尊的 `narrative` 配置将观察与铸造故事归为「第一幕·相遇」，除锈揭字与自选铭文归为「第二幕·发现」，现代发现经历归为「第三幕·重逢」。发现一幕结束可选择「继续故事」进入重逢，或「展开完整铭文」后继续。目录只有三个主入口，完整铭文挂在第二幕下；记忆卡按完成的幕记录进度。内部内容节点 ID 与索引不变，兼容既有续读记录。无 `narrative` 配置的文物仍按原顺序阅读。

鉴宝移至结尾彩蛋，随时可退出，作答前的选项及悬停统一使用中性色。记忆卡改为「我的千年相遇」分享海报：使用压缩后的暖金背景、文物主视觉、一条依据真实探索生成的发现，以及细节、追问、证据三个实际计数。没有查看过的内容不写成个人发现。未填写时提供自选留言和描红入口；添加后分别以手写留言、留言与描红并排的形式排入海报，跳过的字不留空框。进入探索历史时提前生成并缓存海报；预览图片完成解码后才展示，并显式提供宽高，首次冷加载期间隐藏未完成的排版。关闭只收起界面，不释放仍被缓存引用的图片地址，替换缓存或组件卸载时才释放；相同内容重开复用缓存，弹窗和滚动锁定在首帧绘制前就绪，避免打开时闪烁和抖动。预览直接展示最终导出图片，长留言与多字笔迹先量高度再绘制，卡片与操作区作为一组居中，手机保持原尺寸，PC 使用单层左右布局，左侧固定预览框最大宽 458px、高度不超过视口的 65%，保持海报比例并保留保存、分享的位置；左侧仅展示最终海报和保存、分享，移除重复的留言/描红入口及「正在编辑」条；右侧直接提供留言输入和描红操作，交互后进入原位编辑，导出分辨率保持不变，整组预览置于黑色圆角容器，关闭使用容器右上角的轻量叉号，底部仅保留金色实底的「保存图片」和金色描边的「分享」。手机初始「写一句话」「开始描红」仍分别直接打开原留言输入、全屏描红流程；完成任一项后，底部编辑操作才合并为「完善我的记忆卡」入口：编辑入口收为 56px 高的小条目；手机打开紧凑底部编辑面板，最大高度为 72dvh / 500px，使用两行留言框和较小的描红预览；PC 不再打开第二层弹窗，未留笔迹时只显示「开始描红」，有笔迹才显示「重新描红 / 移除笔迹」；右侧集中提供留言、真实描红预览、重新描红和移除笔迹。手机描红复用全屏组件；PC 在右侧原位描红，返回后保留本次草稿，点击「完成编辑」才更新海报，取消编辑不修改已有内容；PC 编辑时左侧保存、分享原位置灰，完成后恢复，更新图片时保留上一帧并固定预览框，避免切换占位造成跳动；留言和描红标题使用用户提供的金色羽毛、毛笔图标，经 imagegen 去除黑底并保留金色纹样后裁剪压缩为透明 WebP，导出海报共用同一套图标；编辑面板、黑色容器和所有操作按钮均不进入导出图片。手机（含 iPad）点击保存时仅弹出「长按图片进行保存呦～」提示，2.6 秒后自动消失，重复点击重新计时；不跳转图片页、不调起系统面板或下载。图片保留原生长按保存能力，PC 保存仍直接下载 PNG。分享在支持文件分享的浏览器内调起系统面板，文件在点击前准备完毕，保留用户手势；不支持时在原卡片下提示，取消不提示成功、不自动下载。支持浏览器文件分享、PNG 下载与长按保存，文件提前准备以保留分享所需的点击手势；不提供小红书配文和发布引导。编辑控件不进入导出图片。

AI 追问只配置在何尊主线的四处关键节点及完整铭文的一处停顿点，普通阅读每处一个问题，提示语随剧情变化。完整铭文的开篇先解释迁居成周；主动展开各段「考」后才推荐本段历史背景、释字或断句问题，收起后恢复阅读问题，查看 ⓘ 字形说明时不补通用题。不同阅读意图分别记录关闭状态，已问过的问题仍会去重。推荐围绕证据与释读边界，不复用剧情选项；已问问题不再补回，关闭对话后同一节点的推荐收起。常驻入口为带呼吸光效的 AI 图标。何尊的回答显示项目已有文物素材头像及角色名，用户提问仍靠右展示。PC 使用右侧抽屉，手机直接全屏打开，顶部暖金色关闭图标返回原故事，不再保留半屏、把手或拉起切换。长回答与依据在面板内滚动阅读，软键盘打开时在剩余可视区内适配高度。对话通过独立弹层保留舞台，旁白、自动揭示计时与模型自转暂停，收起后原位继续。每次提问携带当时的幕、具体热点或铭文段落及探索记录；深入了解沿用该问题的上下文快照。默认回答以 60～120 字为目标，自选深入以 360 字为目标；优先完整回答，前端不按字数硬截断。精选问题提供完整的本地短答，依据面板展示相关档案与来源供核对，不将检索命中等同于逐句事实核验。本地没有 AI 服务时沿用档案兜底，并标明「本地档案回答」。

开场擦雾采用独立的冷凝玻璃层：灰色雾面、细小水珠和顶部暖光，复用现有 3D 文物。模糊与纹理共享 192px 宽的可擦除 alpha 遮罩，擦过后局部清晰；透明面积达到 27% 后用 800ms 淡出余雾，再开始揭幕念白。模型始终使用固定尺寸与独立居中锚点，文案在下方独立区域显示，擦完不再缩放模型容器或挤动位置。「跳过」使用与文字居中对齐的 SVG 箭头。支持鼠标、触摸、跳过与减少动效，旋转或缩放时按比例保留擦痕。后续除锈继续使用原有组件。

探索历史的四个节点等大并排，以连续弧形金线连接，主节点之间点缀小金点；浏览过的圆点和对应线段累计点亮并随探索记录保存，切换、收起或重进页面不清除；点任一节点直接展开对应故事和原有史料依据。手机与桌面均取消中央放大的封面流。时间比例采用紧凑横排，数字资料来源复用全局入口。

第一幕的问答采用轻量文字目录：序号、问题与一句引子用细线分隔，点击后以问题为标题，显示幕名、序号和何尊的预设讲述，不调用 AI。视频仅在选择问题后出现，沿用最初的封面、缩略图播放标识与 45 秒说明，点击「观看完整故事影像」播放现有 MP4；播完后收成一行「已观看 · 再看一次」，切换问题或续读时保留，提前关闭不计为看完。移除独立的「听完整故事」按钮，观察页也不再放视频入口。正文底部以文字入口「再听一个问题」和主要按钮「继续故事」收尾。400ms 转场及视频关闭后的原位续读保持不变，对话回复使用 28px 的绿色何尊头像。

四段预设故事各配一条 AI 追问，分别围绕铸铭纪事、礼器身份、文字工艺和古今心愿，提示语随故事变化。仅此处采用星芒、提示语与问题同属一条暖棕横卡的样式，位于视频入口下方、底部操作上方；其他场景的追问内容和样式保持原有配置。四段都已听过时隐藏「再听一个问题」，若提前选择第四段但还有未听内容，保留选择入口。情感类比在回答和依据中明确标为解释或合理推测。

故事与证据卡片可点击或左滑：正面翻到依据，背面继续后续故事，支持键盘 Enter / Space。正面保留「翻面」，背面恢复「下一张」，最后一张显示「读完了」，同时保留卡片本身的点击与滑动操作。

右下 AI 入口使用 38px 金色聊天气泡与星芒，按 2.8 秒周期轻呼吸，提供按下反馈与减少动效适配。收起对话后若有回答完成，入口显示真实的新回复红点；打开对话即清除，切换文物时重置。第一幕视频在点击手势内同步挂载并带声播放，浏览器拦截时显示明确的重试按钮，不降级为静音播放；播放时暂停背景音乐，关闭或播完后恢复用户原先开启的音乐，原先静音则保持静音。

## FACT / STORY 双层数据模型

AI 证据联动支持三类登记目标：铭文「宅兹中国」、器身兽面纹、时间线「1963 年 · 重逢」。首次进入何尊对话提供「你为什么这么重要？」推荐，也支持兽面纹意义、发现经过等自然问法。真实 AI 请求使用 answer / factIds / suggestedActions 协议；旧版文本响应或离线档案回答按已关联史料推导建议，界面保留真实回复来源标识。执行前同时验证文物、动作类型、真实目标、史料编号与回答中的目标内容，不接受任意 DOM、链接或代码。

用户点击建议才打开独立证据层：铭文复用完整长卷与描金浮字；纹饰复用 3D 何尊，平滑转向预设角度、高亮兽面纹热点，展示形态说明与寓意的理解边界，模型不可用时明确降级为插画；时间线直接聚焦并展开「重逢」，同时显示故事及史料，区分 1963 年发现、1965 年入藏、1975 年发现铭文三个时间点。原章节与聊天保持挂载，证据层不改 stage、chapterIndex 或全局剧情上下文；「返回对话」保留消息及滚动位置，「回到故事」继续原进度。实际打开铭文、时间线或完成纹饰定位后才记录查看行为，显示来源后才记录来源条目；记忆卡与导出图片汇总三类实际查看过的证据，不虚报主线完成或理解程度。普通「探索历史」按当前故事节点初始化，读完主线后仍聚焦「重逢」，不再因为已完成三幕而强制跳到「今天」。

核验：`npm run check:evidence` 覆盖多种问法、目标与来源白名单、结构化/旧版/离线响应、背景上下文保持和记忆记录。手机、桌面的原有对话布局及其他情境追问保持原配置。

- **FACT 层**（`src/types/artifact.ts` 的 `Fact`，含 `confidence` 与 `source`）：可验证的历史事实，AI 与文案只能基于它展开。
- **STORY 层**（热点故事、时间线旁白等）：为可读性做的文学化表达，可以感性，但不能与关联的 FACT 矛盾。

每件文物的全部文本内容集中在自己的档案文件里（`src/data/artifacts/hezun.ts`、`changxin.ts`）。

> ⚠️ 长信宫灯的史实**尚未逐条核对**，档案里一律标 `confidence: "inferred"`、`source` 写明待补出处，界面上会显示为「合理推测」。`npm run check:artifacts` 会持续提醒这件事。正式发布前必须核实。

## 三维模型资产

线上使用 `public/models/<id>.glb`（何尊 4.5MB / 27 万面，长信宫灯 5.1MB / 37.5 万面），由原始扫描件压缩生成：

```bash
node scripts/pack-model.mjs hezun
node scripts/pack-model.mjs changxin 0.25   # 第二个参数是网格简化比例
```

简化比例**不要跨文物照抄**：`0.18` 是按何尊（回转体 + 纹饰）调的，人物造型（宫灯的面部与手部）压太狠会先糊在那里，所以宫灯用 `0.25`。

原始扫描件（各约 100MB）**存放在仓库外** `~/DeltaChallenge-assets/`，脚本默认从那里读（可用 `ASSETS_DIR` 覆盖）。移出仓库不只是因为 GitHub 的 50MB 警告线，更要紧的是 Cowork 的 pack 是整目录 copytree、**不看 `.gitignore`**——素材留在仓库里会让发布包上传超时。

展示分三档自动降级（`src/utils/artifactEvaluator.ts`）：模型可用且支持 WebGL 时走 `3d`，加载中显示带真实进度的中性占位，失败则回落到手绘插画（按档案的 `illustrationId` 分发），任何异常都不阻塞体验。
